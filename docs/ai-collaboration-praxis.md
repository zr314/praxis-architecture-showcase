# 与 AI 协作完成的项目：Praxis

**项目地址：**https://github.com/zr314/praxis-architecture-showcase

## 项目描述

我与 AI 协作完成了 Praxis——一个面向长生命周期任务的可恢复多智能体运行框架。项目背景是，传统 ReAct Agent 更适合短任务，在长时间编码、复杂工具调用和多智能体协作中，容易受到上下文膨胀、进程中断、任务状态丢失以及权限失控等问题影响。因此，我希望构建一套不依赖固定墙钟或少量工具调用上限，能够持续执行、动态委派任务并在异常后恢复的 Agent Harness。

在协作过程中，我负责确定项目目标、总体架构和关键技术取舍，例如由 LLM 自主选择直接执行、委派 Subagent 或展开动态 DAG，Root 与 Child 使用同构运行时，而权限、预算和状态一致性由 Runtime 强制保证。AI 作为结对工程伙伴，协助我扫描 TypeScript 代码和 Git diff、梳理调用链、分析运行日志、提出候选方案、完成局部代码修改，并执行定向测试和真实任务回归。整个开发过程遵循“提出假设—定位证据—小步修改—定向验证—真实测评—文档沉淀”的闭环；对于 AI 给出的方案，我会结合项目的长期目标进行审核，而不是直接接受生成结果。

项目中最困难的问题是长任务的可靠执行。为此，我们使用 SQLite 持久化 Workflow、Attempt、Lease 和 Artifact，实现并行 fan-out、quorum join、cross-review 以及进程重启恢复；通过签名 ContextPacket 和 Capability Bundle 固化 Subagent 的任务目标、证据合同与最小权限；同时分离会话语义和 Workflow 执行事实，设计 semantic checkpoint 与稳定 Prompt 前缀，使上下文压缩后仍能保留未完成事项、文件状态和前驱结果。对于测评中暴露的问题，我们依据 trace、Session Journal 和官方 verifier 区分模型错误、Provider 异常、基础设施故障与 Praxis 框架缺陷，再在主干完成修复和回归，避免通过修改测评脚本掩盖问题。

最终，Praxis 在同模型 Harness-Bench 三题测评中取得 **0.9219** 的综合分，对照框架 Pi 为 **0.8319**，同时模型请求数减少 **36.1%**；在 AgentDojo 小样本中完成 **7/7** 项任务，两项 Prompt Injection 攻击目标均未达成，危险工具执行数为 **0**。在真实长任务中，框架完成了 **148 轮、147 次工具调用**的扩展编译任务，以及持续约 **35 分钟**的 CompCert 编译任务，二者均通过官方验证。

这个项目让我认识到，高质量的人机协作并不是把项目整体交给 AI，而是由人负责目标定义、架构决策和验收标准，让 AI 加速代码理解、方案探索、实现与重复验证，再通过 Git、自动化测试、运行日志和 benchmark 对结果进行约束。通过这种协作方式，AI 从一次性的代码生成工具变成了可审计、可迭代的工程伙伴。
